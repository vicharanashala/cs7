• Student writes their description.
• Optionally uploads a screenshot.
• Selects a category (or “Other”).

	1. FAQs → If an answer exists, show it. Ask: “Does this answer your question?”

*** Admin Dashboard Plan by Harshdeep Sharma ***

Purpose
This document is the admin-branch implementation spec for faq-Avatar. 

High-Level Objective
The admin experience is the institutional control plane for knowledge governance. It should help administrators:
- understand overall knowledge health,
- identify unanswered or low-quality content,
- manage FAQ publishing and editorial review,
- control user access and role changes,
- monitor moderation capacity, and
- keep a compliance-ready audit trail.

Dashboard Scope
The admin dashboard is not a single page. It is a set of connected surfaces that work together as one operational workspace.
- Overview and mission control live in /admin/intelligence.
- Editorial quality review lives in /admin/faq-quality.
- Knowledge-base maintenance lives in /admin/faqs and the FAQ editor routes.
- Search-gap remediation lives in /admin/unanswered-searches.
- Crowd and issue concentration analysis lives in /admin/issue-heatmap.
- Workforce control and permissions live in /admin/users and /admin/moderation-load.
- Institutional traceability lives in /admin/audit-logs.

Shared Behavior and UX Principles
- All admin pages should use the same premium dashboard shell, card system, and table styling already established in faq-main.
- All content changes should preserve audit context.
- Admin actions should favor review, edit, archive, and moderation workflows over destructive operations.
- Search gaps and FAQ quality issues should surface as actionable items, not just analytics.
- Shared knowledge-base surfaces should remain consistent for moderator and admin access.

Navigation and Placement
The admin nav should expose the pages that are operationally important for administrators:
- Admin Overview / Intelligence
- FAQ Management
- User Management
- Chatbot Feedback if present in the broader dashboard shell
- Settings if the branch includes settings parity
- Moderation-related utilities that administrators are allowed to access

1. /admin/intelligence
This is the admin mission-control page and the main overview surface.

Primary responsibilities
- Summarize institutional knowledge health.
- Highlight urgent issues that require action.
- Surface the biggest search gaps and FAQ quality risks.
- Show whether moderation throughput is healthy or blocked.

Key content blocks
- Unresolved Questions metric.
- No-Result Searches metric.
- FAQs Needing Review metric.
- Average Resolution Time metric.
- Action Required cards.
- Issue Heatmap preview.
- Top Unanswered Searches.
- FAQ Quality Alerts.
- Audit trail navigation.

Behavior details
- Metric cards should include current value, trend, and a short implication statement.
- Action cards should map to concrete next steps such as creating FAQs, reviewing stale content, or assigning moderation work.
- Issue heatmap content should show concentration of questions and searches by category and day.
- Unanswered searches should link directly into FAQ creation with prefilled title and answer scaffolding.
- FAQ quality alerts should link directly into FAQ editing for the selected record.

Expected editorial logic
- If unresolved questions rise, the page should push the operator toward moderation capacity and backlog review.
- If unanswered searches rise, the page should highlight missing knowledge coverage.
- If FAQs needing review exist, the page should treat them as editorial risk.
- If average resolution time rises above the healthy threshold, the page should imply queue bottlenecks.

2. /admin/issue-heatmap
This is the category concentration and pattern-analysis page.

Primary responsibilities
- Show where users are searching or asking questions the most.
- Help administrators spot hotspots by category.
- Compare recent pressure across time windows.

Controls and filters
- 7-day view.
- 14-day view.
- 30-day view.
- 90-day view.

Displayed information
- A heatmap matrix combining search and question volume.
- Category narratives that explain why a category is hot.
- A ranked narrative section for the most significant categories.

Behavior details
- The selected range should refresh the heatmap and the category narrative cards together.
- Hover or inspection behavior should explain which category-day intersections are driving pressure.
- The page should be useful for both editorial planning and moderation staffing.

3. /admin/unanswered-searches
This is the knowledge-gap remediation page.

Primary responsibilities
- Show what users are searching for but not finding.
- Help administrators turn repeated search failures into new or improved FAQs.

Controls and filters
- Most Common.
- Most Recent.
- Highest Impact.

Displayed information
- Search query.
- Occurrence count.
- Last seen date.
- Suggested FAQ title.
- Related category.
- Create FAQ action.

Behavior details
- Search clusters should be ranked so the most important gaps rise first.
- The Create FAQ action should prefill the FAQ editor with the suggested title and structured guidance text.
- If a cluster is tied to a related category, that category should preselect in the editor.
- The page should be designed for fast remediation, not passive reporting.

4. /admin/faq-quality
This is the editorial risk and quality-control console.

Primary responsibilities
- Detect low-quality FAQs.
- Prioritize content that should be rewritten or archived.
- Give administrators a decision-making workspace for editorial review.

Controls and filters
- All.
- Rewrite Candidates.
- Archive Candidates.

Displayed information
- FAQ title.
- Quality score.
- Helpfulness ratio.
- View count.
- Action classification.
- Detailed narrative for the selected FAQ.
- Quality breakdown bars.
- Trend sparkline.

Available actions
- Edit FAQ.
- Archive FAQ.
- Mark Reviewed.

Behavior details
- Selecting a FAQ should update the right-side detail panel.
- Quality breakdown should explain the weighted signals behind the risk score.
- Trend sparkline should show the recent direction of quality.
- Actions should update editorial state without breaking the overall workflow.

5. /admin/faqs
This is the shared knowledge-base control center.

Primary responsibilities
- List all FAQs in a structured table.
- Support create, edit, archive, publish, and review operations.
- Give administrators direct control over the content system.

Filters and controls
- Status filters: all, draft, published, needs review, archived.
- Category filter.
- Minimum quality filter.
- Row selection for bulk actions.
- Create New FAQ action.

Displayed columns
- FAQ title.
- Status.
- Category.
- Quality score.
- Last updated information.
- Actions.

Bulk actions
- Bulk publish.
- Bulk mark for review.
- Bulk archive.

Additional content
- CSV import guidance for structured ingestion.

Behavior details
- The table should reflect the selected filters immediately.
- Category and quality filters should narrow the operational list, not just the visual presentation.
- Bulk actions should operate on the selected FAQ rows only.
- Import guidance should be visible so the admin knows the expected file format.

6. /admin/faqs/new and /admin/faqs/:id/edit
This is the FAQ editor and publishing workspace.

Primary responsibilities
- Create new FAQs.
- Update existing FAQs.
- Check similarity before publishing.
- Capture editorial justification when duplicates are possible.

Editor fields
- Title.
- Summary.
- Answer.
- Categories.
- Tags.
- Status.
- Duplicate override reason.

Editorial controls
- Create.
- Save updates.
- Publish.
- Archive.
- Change review state.

Quality and safety logic
- Similarity checks should run before final publication.
- If a high-similarity FAQ exists, the editor should force a human review of the duplicate risk.
- If the admin intentionally keeps a similar FAQ, the duplicate override reason should be required.

Behavior details
- Creating from search-gap links or community-answer candidates should prefill the editor.
- Editing should preserve previous content context and editorial notes.
- Status changes should stay aligned with the moderation and quality consoles.

7. /admin/users
This is the access-control and user-administration page.

Primary responsibilities
- Review all users in the system.
- Change user roles.
- Suspend or restore accounts.
- Preserve accountability for access changes.

Displayed fields
- Name.
- Email.
- Role.
- Status.
- Activity dates.
- Action button.

Available actions
- Change role.
- Suspend.
- Activate.

Behavior details
- Role changes should alter permissions immediately.
- Suspension should preserve existing content while preventing new submissions.
- Confirmation dialogs should be required for access changes.
- The page should show joined and last-active dates so admins can judge account freshness.

8. /admin/moderation-load
This is the staffing and throughput dashboard for moderation work.

Primary responsibilities
- Show whether moderation capacity is keeping up with incoming work.
- Help assign moderators based on backlog and category pressure.
- Show moderator performance across the queue.

Displayed sections
- Pending Queue Depth trend.
- Categories Consuming Review Time.
- Moderator Performance.
- Resolution Funnel.

Behavior details
- Queue depth should show whether incoming work is rising faster than reviews.
- Category backlog should show where moderation attention is needed most.
- Moderator performance should compare approvals, rejections, and average time.
- Resolution funnel should explain where students drop out of the knowledge path.

9. /admin/audit-logs
This is the compliance and traceability surface.

Primary responsibilities
- Provide a filtered institutional audit trail.
- Support compliance review and investigation.

Behavior details
- The page should exist as a clean destination for traceability even if the implementation is lightweight.
- Admin navigation should always provide access to this trail from the intelligence view.

FAQ Management Shared-Surface Rules
- FAQ Management is shared between moderators and admins.
- Categories and tags should live inside the FAQ Management experience rather than separate sidebar entries.
- Any admin-side FAQ edit should remain visible to moderator workflows.
- Any quality, search-gap, or moderation-candidate signal should be actionable from this shared surface.

Admin Documentation Checklist
- Mirror faq-main routes and page names.
- Preserve the mission-control layout on the intelligence page.
- Keep FAQ creation/editing tightly connected to search gaps and quality alerts.
- Keep role and access management explicit and auditable.
- Keep analytics pages readably segmented and action-oriented.

Implementation notes
- This file should be treated as the authoritative admin-branch documentation for faq-Avatar.
- If the admin branch grows, add new pages under the relevant section instead of replacing the current structure.
- Keep wording aligned with the shared dashboard style already established in the branch.

Additional Suggestions to Make the Admin Surface Stronger
These are not replacements for the pages above. They are additive improvements that can make the platform feel more complete, faster, and more decision-ready.

1. Create a single role-aware home dashboard for admins
- Add a unified landing page that surfaces the most important admin KPIs first, before the user chooses a drill-down page.
- Include unresolved question counts, editorial risk counts, moderation backlog, FAQ quality drift, and unanswered-search growth in one glance.
- Add “next best action” cards so the admin always has a clear place to start.

2. Add saved views and pinned filters everywhere data is tabular
- Let administrators save filter combinations for FAQ management, unanswered searches, user management, and audit logs.
- Allow pinned views such as “High-risk FAQs,” “Stale unanswered searches,” or “Recently suspended users.”
- Add quick-switch chips so the same view can be revisited without reconfiguring controls every time.

3. Build an event-driven live update layer
- Push moderation and editorial changes to the admin screens in real time so counts, queues, and quality alerts do not feel stale.
- Prefer lightweight server push or websocket-style updates for queue counts, search clusters, and review status changes.
- Keep the polling fallback so the system still works if real-time transport is unavailable.

4. Add bulk action previews and undo-safe operations
- Before bulk archive, bulk publish, or bulk role change, show a preview of the affected records.
- Add a short undo window for safe recovery when a bulk operation was applied too quickly.
- Log the full before/after state in the audit trail for accountability.

5. Expand the FAQ Management workflow into a true content lifecycle
- Add explicit lifecycle states such as draft, under review, approved, published, stale, and archived.
- Surface stale content automatically when a FAQ has low engagement, rising flags, or rising duplicate detections.
- Add editorial ownership so specific admins can be accountable for high-impact FAQs.

6. Add advanced search and command-driven navigation
- Extend the command palette so admin users can jump directly to records, open pages, or create content from keyboard search.
- Allow search across FAQ titles, user names, audit events, and unanswered query clusters from one surface.
- Make the command palette the fastest route to any object in the admin system.

7. Add analytics that tell a story, not just a number
- Show trend deltas, anomaly markers, and “why this matters” text wherever a dashboard number appears.
- Add category-level drift analysis to reveal what is becoming more common, not only what is currently large.
- Add a simple “What changed since yesterday?” panel on the intelligence page.

8. Add queue ownership and assignment controls
- Allow administrators to assign unresolved items or moderation load to specific moderators.
- Add workload balancing indicators so queues can be redistributed when one moderator is overloaded.
- Include follow-up reminders and SLA-style escalation rules for items that remain untouched.

9. Add a cross-linking knowledge graph inside admin workflows
- Let admins jump from a FAQ to related unanswered searches, related community questions, related tags, and related audit events.
- Show related content side-by-side when editing or reviewing an item.
- Use these relationships to make remediation more contextual and less repetitive.

10. Add export, reporting, and scheduled summaries
- Allow CSV or JSON export for FAQ lists, unanswered searches, user roles, and audit events.
- Add scheduled summary emails or in-app summaries for leadership review.
- Let the system generate weekly and monthly institutional snapshots.

11. Add better accessibility and keyboard workflow guarantees
- Ensure every admin table, modal, drawer, and filter cluster is keyboard accessible.
- Keep focus states, visible labels, and shortcut hints consistent across pages.
- Make bulk workflows usable without requiring pointer interaction.

12. Add performance safeguards for scale
- Cache expensive analytics queries and prefetch the next likely admin page after login.
- Virtualize long lists in FAQ management, unanswered searches, and user management.
- Keep responses paginated or windowed so the interface remains fast even as the data set grows.

13. Add policy-aware audit enrichment
- Record the reason behind key admin actions, not only the action itself.
- Attach decision notes to FAQ archive, publish, role change, and moderation reassignment actions.
- Surface a compact audit summary on each major record so future admins can understand history without opening a separate log.

14. Add smarter onboarding for new admins
- Provide a guided first-run checklist that explains the dashboard in order of priority.
- Add “what to do next” hints beside the main metrics.
- Surface sample workflows so a new admin can understand how intelligence, FAQ editing, and audit review connect.

*** Moderator Dashboard Plan by Harshdeep Sharma ***

Purpose
This document is the moderator-branch implementation spec for faq-Avatar. 

High-Level Objective
The moderator experience is the real-time moderation control center for the platform. It should help moderators:
- triage incoming answers and questions,
- resolve unresolved questions quickly,
- request edits when answers need improvement,
- link duplicate questions,
- identify FAQ conversion candidates, and
- move clean content into the shared knowledge base.

Dashboard Scope
The moderator dashboard is a connected set of work surfaces.
- Queue triage lives in /moderator/queue.
- Interactive moderation happens in /moderator/console.
- Personal throughput and operational health live in /moderator/analytics.
- Knowledge promotion lives in /moderator/faq-candidates.
- Shared knowledge-base maintenance happens in /admin/faqs.

Shared Behavior and UX Principles
- Moderation pages should favor speed, clarity, and keyboard-friendly operation.
- Queue pages should always make the next action obvious.
- The moderator should be able to see context, answer text, and pending actions without leaving the console.
- The system should encourage review, correction, and escalation rather than destructive handling.
- Shared FAQ management should be reachable from the moderator flow.

1. /moderator/queue
This is the moderator review queue and the first stop for moderation work.

Primary responsibilities
- Present all pending moderation work in a compact operational table.
- Support bulk processing where the task type allows it.
- Let the moderator jump into the full console for detailed review.

Filters and controls
- All.
- Pending Answers.
- Unresolved.
- Duplicate Candidates.
- FAQ Candidates.
- Sort by Priority.
- Sort by Age.
- Sort by Category.

Displayed columns
- Selection checkbox.
- Type.
- Title.
- Category.
- Priority.
- Age.
- Action.

Available actions
- Bulk approve.
- Bulk reject.
- Bulk resolve.
- Open Console.
- Review selected item.

Behavior details
- The queue should default to priority-first operation.
- Selecting rows should enable relevant bulk actions.
- The queue should allow quick navigation to a specific item in the console.
- Empty queue state should communicate that moderation is ahead of the curve.

2. /moderator/console
This is the main moderation workspace and the core action surface.

Primary responsibilities
- Show the selected queue item in full context.
- Let moderators review answers and questions without leaving the page.
- Provide decisive actions for approval, rejection, correction, and escalation.

Layout and structure
- Left pane: priority queue.
- Right pane: detailed content review.
- Bottom bar: action controls and shortcuts.

Context and content blocks
- Question context panel.
- Pending answer review panel.
- Open-question answer review panel.
- Duplicate linking field.
- Submitted answers list when the item is an open question.

Available actions
- Approve.
- Reject.
- Request Changes.
- Resolve Question.
- Mark for FAQ Conversion.
- Mark Duplicate.

Keyboard shortcuts and interaction
- J / K should navigate through queue items.
- A should approve.
- R should reject.
- C should request changes.
- Escape should reset to the first queue item.

Behavior details
